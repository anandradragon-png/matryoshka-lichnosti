# CLAUDE.md — правила проекта «Матрёшка Личности» (прототип)

Этот файл задаёт архитектурные правила, чтобы при правках ничего не «слетало».
Читать перед любыми изменениями в `prototype/`.

## Что это
Статический прототип сайта психоподдержки. Ванильные HTML/CSS/JS, без сборки и
без бэкенда. Данные хранятся только в `localStorage` браузера. Деплой — GitHub
Pages из этой папки (`prototype/` = корень git-репозитория).

## Структура
- `index.html` — разметка всех секций одной страницы + подключение скриптов в конце `<body>` с `defer`.
- `styles.css` — все стили. БЭМ-подобные классы.
- `js/` — логика, разбита на файлы по секциям (см. ниже). Классические скрипты, делят общую глобальную область.
- `dars-data.js` — данные раздела «дарсы»; экспортирует `window.YupDar`; грузится ПЕРВЫМ.
- `docs/` — HTML-черновики юридических политик (152-ФЗ). Все с заглушками `[реквизиты АНО]` — до боевого запуска заполнить и отдать юристу.
- `test/` — smoke-тесты на jsdom (`npm test`). `eslint.config.js`, `.prettierrc.json` — качество кода. `.github/workflows/ci.yml` — CI (линтер+тесты).

### Карта модулей `js/` (порядок подключения = порядок в index.html, важен!)
1. `core.js` — меню, скролл-навигация, объект `ML_KEYS` (реестр ключей localStorage).
2. `util.js` — общий `escapeHtml`. Подключается рано.
3. `chat.js` — чат-бот (демо-сценарий/живой YandexGPT). В рантайме зовёт `EMOTION_GUIDE`, `PRACTICES`, `openPractice` из practices.js.
4. `organizer.js` — органайзер эмоций, дневник, статистика, стрик. Колесо Плутчика.
5. `map.js` — карта личности (Дары/Поля), считает через `window.YupDar`.
6. `practices.js` — каталог практик и модалка практики.
7. `billing.js` — переключатель тарифов + заглушка оплаты.
8. `account.js` — личный кабинет: вход/регистрация, сид-аккаунты, админка, отзывы.
9. `cookie.js` — cookie-баннер.

**ВАЖНО про модули:** файлы делят одну глобальную область (это ещё НЕ ES-модули). Функции/данные видны между файлами по имени. Из-за этого: (а) порядок подключения важен — при добавлении зависимости следи за тем, что нужное объявлено раньше по коду; (б) `no-undef` в ESLint отключён для `js/*.js` (линтер не видит межфайловые глобалы). Перевод на настоящие ES-модули с `import/export` — отдельная запланированная задача (после пилота), тогда `no-undef` вернём.

## Правила, которые нельзя нарушать
1. **Ключи localStorage — только через `ML_KEYS`** (объект в `js/core.js`). Не писать строку `'ml_...'` напрямую. Новый ключ — сперва зарегистрировать в `ML_KEYS`.
2. **Порядок скриптов**: строго как в разделе «Карта модулей». Все с `defer`. `dars-data.js` — первым.
3. **Именование CSS-классов**: осмысленные префиксы по секции (`am-` — account modal, `pm-` — practice modal, `pl-` — колесо Плутчика, `wk-` — стрик, `chat-`, `cookie-`, `b2b-`, `map-`). НЕ использовать короткие generic-имена вроде `.l1` — ранее был конфликт (пилюли Плутчика ↔ слои матрёшки). Слои матрёшки теперь `.layer--1…--5`. Новый компонент → свой префикс.
4. **Экранирование пользовательского ввода**: любой текст от пользователя перед вставкой в DOM пропускать через `escapeHtml()`. Не собирать HTML конкатенацией сырых строк.
5. **Согласия 152-ФЗ**: каждая политика — отдельный файл в `docs/` и отдельная обязательная галочка в форме регистрации. Не объединять в одну галочку. Факт согласия с датой писать в запись пользователя (`consent`).
6. **Монетизация для НКО**: не возвращать фиксированную регулярную абонплату (запрет для АНО). Только индивидуальные договоры.

## Безопасность (важно понимать границы)
- Текущая «авторизация» — фейковая, на клиенте. Пароли лежат в localStorage и в публичном исходнике. Это осознанно и временно.
- Настоящая защита (бэкенд, хеширование, серверная валидация) — задача этапа после получения юрлица.
- Секреты (ключи ИИ, service account) хранить ТОЛЬКО на сервере. В репозиторий — никогда (см. `.gitignore`).

## Чат-бот
- `BOT_API_URL` в `js/chat.js`: пусто → работает демо-сценарий; вписать URL Cloud Function → бот отвечает через YandexGPT.
- Кризисная проверка на клиенте (телефон доверия) остаётся как страховка независимо от режима.

## Проверка изменений
- `npm run lint` — ESLint, `npm test` — smoke-тесты (jsdom), `npm run check` — оба. Прогонять перед коммитом.
- `npm run format` — Prettier (по требованию; сразу всё не переформатировано, чтобы не раздувать диффы).
- Локальный превью-сервер обслуживает эту папку. Браузер иногда отдаёт устаревшие скрипты из кэша — перед проверкой делать `fetch('/js/core.js',{cache:'reload'}).then(()=>location.reload())` (или нужный файл).
